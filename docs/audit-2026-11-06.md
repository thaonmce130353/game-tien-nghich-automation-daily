## Findings and fixes

1. **Thủ Vệ Tứ Phái: Start does nothing mid-round.** After 3 wins (status 1, no `is_quit`) the formation Start sent nothing (no 4th 14010/11033). The run logged an error and went straight to Chiến Lệnh, skipping the milestone claim (`sd11032`). After a page reload 11030 reported status 2 and the game continued the same round (4 more fights, restart, 3 milestones claimed, +100). Fix (`sect-defense.js`): on that failure, refresh the status once (`resumeTries`) so status 2 reopens the buff panel; an 11033 reply without `enter_id`, a seen round end (`is_quit`/status 3) or a restart means done today → milestone claim; any other give-up after ≥1 fight still claims milestones with a warning.
2. **Vực U Minh sends fights with an empty team.** The feature called `YMAbyssCtrl.startFight(1)` right after opening the formation board. The `1` is a fake hero count that skips the game's own check, so the server refused (`11001` res 0, 105002 "Đội hình … trống"). In single mode the 2.4 s tick also counted an attempt while the board was still open (3 "tries" in 9 s). Fix (`underworld-abyss.js`): no direct `startFight`; the formation hook arranges, verifies and presses Start; while the board/fight/result is open the feature waits without counting a try; when "Bỏ qua trận" is off the feature drives the board itself (`abyssDriveEmbattle`).
3. **Audit false positives.** `11020` (Tứ Linh fight) and `32061` (Ảo Cảnh round start) are answered under other command numbers; they no longer count as "không thấy phản hồi" (`AUDIT_REPLY_ELSEWHERE`). `RankCtrl` added to Vực U Minh's expected controllers (opening the abyss screen loads its ranking).

Still open: Đấu Tiên Đài always picks the lowest-power opponent even when it is above our power (5/5 losses); `32062` shows 2 missing replies per run (the last pair of each round is answered by the round result).
