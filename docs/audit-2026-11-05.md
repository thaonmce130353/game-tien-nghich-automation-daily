## Fixed in this session

1. **Thủ Vệ Tứ Phái, endless `sd11030` loop.** After giving up on the buff it went back to `status`, which reported "fighting", reopened the buff screen and gave up again: 52 status requests in 4 minutes until stopped. It now goes to the reward claim and finishes.
2. **Thủ Vệ Tứ Phái, "Buff chọn bị lỗi".** The game sends one buff list per stage (reply 11033). After an accepted pick we picked again on the same stale screen, the server refused, and the try counter (keyed to the stale stage id, never reset after a win) gave up although the fights were being won. Now: one pick per list, then `clsEBuffUi` and the fight step reopens a fresh list; counters reset after a win. Live: 4 picks, 4 accepted, stages 1146 → 1174.
3. **Thủ Vệ Tứ Phái, restart after the day's run ended.** "Bắt đầu lại" opens the team screen but the server starts no new run; this now ends with an info line instead of a misleading "could not arrange the team (6/6)" error.
4. **Battle skip (all features).** It skipped the game's `transRoundFightList` step, and for Vấn Đạo it finished the fight before the 18144 reply existed, so the game threw `Cannot read properties of undefined (reading 'damage')` inside its fight-finish code. Both are fixed (Node test of the hook; live, Vấn Đạo was already done today).
5. **Cửu Uyển Nhi.** Server reply `218015` "Đã vượt hết tầng" (everything cleared) is now "nothing to sweep" (info), read at once from the reply instead of waiting 20 s and logging ❌. Live: step ends ✅.
6. **Screens and popups after a run.** Single runs never closed anything (only Quick Run did, between steps). Every run now closes the screens it opened, and single runs sweep late reward/notice popups 2.5 s later. Live: Trợ Chiến, Tiên Minh, Thủ Vệ, Cửu Uyển Nhi all ended on the main city screen.
7. **Silent errors.** The scheduler tick swallowed exceptions; they are now recorded by the audit.
